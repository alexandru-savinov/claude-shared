Define three reusable Claude Code agent types — `forge`, `reader`, `adversary` — as `content/agents/*.md` files, so the delegation rules Alexandru currently has to retype into every task prompt live in the agent's own frontmatter and system prompt instead.

## Context

Today `content/agents/` holds one file, `nix-security-reviewer.md`. It has a proven shape: YAML frontmatter (`name`, `description`, `tools`, `model`) followed by a markdown system prompt, and its `tools:` line uses scoped `Bash(<cmd>:*)` prefixes rather than a bare `Bash`. Per `README.md`, files under `content/agents/` are symlinked live into `~/.claude/agents` by the home-manager module and become dispatchable after `nix flake update claude-shared` + a host rebuild — this plan only authors the files; deployment and any first live dispatch happen after merge, outside this plan's scope.

Three real incidents motivate the three types, and each type's file should make the corresponding failure as hard to reach as this deployment actually allows — see the enforcement finding below for what that ceiling really is:

1. **2026-08-19** — an agent holding raw public-comment capability (`gh pr comment`) plus a "report findings on the PR" mandate posted the mechanism of an unpatched CRITICAL vulnerability onto a public PR.
2. **Triage-tool mishap** — a recon/audit pass probing a CLI's `--help` output caused a write into `sidequests.jsonl` (the `--help` text got captured as a quest).
3. **Adversary check that couldn't fail** — a freshly built regression check passed green while the exact bug it existed to catch was live, twice. An adversary agent's job is specifically to break things and report what did and didn't break, including negative results.

**Baseline before this plan starts:** `main` is green — `git status` clean, no open conflicting PRs touching `content/agents/`. Confirmed in Task 0.

**Capability-gate enforcement — tested empirically, 2026-08-20, not assumed.** Before writing the three files, this plan's author dispatched the ALREADY-DEPLOYED `nix-security-reviewer` agent (tools: `Read, Grep, Glob, Bash(systemctl:*), Bash(tailscale:*), Bash(nix eval:*)` — no `Write`/`Edit`) and asked it to (a) write a file and (b) run a Bash command outside its declared prefixes. Result: it wrote the file anyway via `Bash` with `echo ... > file` (no Write tool needed — Bash sufficed), and it ran `git log -1`, a command matching none of its three declared prefixes, with no refusal or error. `module/default.nix`'s `baseSettings` sets `permissions.defaultMode = "auto"` and `skipDangerousModePermissionPrompt/skipAutoPermissionPrompt = true` fleet-wide — which explains it: the `Bash(<cmd>:*)` prefixes are a permission-*approval* matcher (what would need confirmation, absent auto-mode), not a per-invocation sandbox on the Bash tool itself. Once any `Bash(...)` entry makes the Bash tool available to an agent at all, that agent can run arbitrary shell in this deployment, including writes, regardless of how narrowly the prefixes were scoped.

This falsifies the naive version of "just scope the Bash prefixes" as a hard capability gate, and it changes the design:

- **The only VERIFIED write-safe configuration is granting no Bash tool at all.** `Read`, `Grep`, `Glob` are first-class, non-shell tools (not wrappers around a shell), so they carry no equivalent escape observed or plausible here.
- **`forge` and `adversary` cannot avoid Bash** — committing/pushing/opening a PR, or running a test suite to try to break something, requires a shell. For these two, the `tools:` line and the exclusion of `gh pr comment` / `gh pr edit` / `gh api` / write-tools (for `adversary`) are declared-intent and behavior-steering — they reduce what the model reaches for and would matter the moment this fleet's permission mode stops being blanket-`auto` — but they are **not**, today, a hard technical boundary. This plan states that plainly in each file's own system prompt (Tasks 1 and 3) rather than implying a guarantee the fleet doesn't back.
- **`reader` gets rebuilt around this finding**: no Bash entries at all, only `Read, Grep, Glob`. This sacrifices shell-based recon (`git log`, `gh pr view` as commands) in exchange for the property actually being true: a `reader`-typed agent structurally cannot write, under this deployment, not just "is instructed not to."

This is a materially different (smaller, more honest) claim than a first draft of this plan made before the probe ran, and it is the single most important thing this plan changes if a future editor is tempted to re-add scoped Bash prefixes to `reader` for convenience: don't — it was tested and does not hold.

## Constraints
- Scope is `content/agents/*.md` and `content/agents/fixtures/*.md` only. Do not touch `module/default.nix`, `content/skills/`, `content/commands/`, `PLAN.md`, `README.md`, `SECURITY.md`, or any host config.
- Never commit or push to `main`. Work happens on `plan/agent-definitions`; land it via a PR, never a direct push to `origin/main`.
- `reader` holds `Read, Grep, Glob` and nothing else — zero Bash entries, scoped or not. This is the one property this plan can mechanically prove holds at rest (grep for the absence of the string `Bash`) and is expected to also hold at dispatch time, because there is no Bash tool to escape through.
- `forge` may hold `gh pr create` but never `gh pr comment`, `gh pr edit`, or `gh api`, and never a bare `Bash`. `adversary` holds no write tool and never a bare `Bash`. Both facts are checked at rest (grep) but are NOT proven to hold at dispatch time under this fleet's `permissions.defaultMode: auto` — say so in both files, don't imply a sandbox that was tested and found absent.
- `adversary` uses `model: opus`; `forge` and `reader` use `model: sonnet`.
- Every checklist item's closing check must include a negative arm (a deliberately-broken copy that proves the check can fail) before it is trusted — a check that cannot fail is not a check.
- Do not perform a live agent dispatch as part of this plan's checks — that requires deployment (a rebuild) outside this plan's scope. The one live probe this plan relies on (the 2026-08-20 `nix-security-reviewer` test) was run manually by this plan's author before writing it, not by a ralphex task, and is cited as evidence in Context, not re-run here.
- Delete every `/tmp/*-negative-test.md` scratch file created during checks before finishing its task — they are proof artifacts for the transcript, not repo content.
